# Zyphra File Analyzer Bot — Render Web Service

This version runs the Telegram bot as a Render Web Service using a Telegram webhook.
It no longer requires long polling.

## Render

Use the repository root Blueprint (`render.yaml`).

The Blueprint creates:

- Node.js Web Service
- `/health` HTTP health endpoint
- Telegram webhook at `/telegram/webhook`
- `BOT_TOKEN` as a secret
- automatic `RENDER_EXTERNAL_URL` discovery
- SQLite database at `data/bot.db`

### Environment variables

Required:
- `BOT_TOKEN` — set this only in Render Environment.

Configured by the Blueprint:
- `ADMIN_ID=7842341917`
- `FREE_LIMIT=5`
- `FREE_MAX_MB=10`
- `VIP_MAX_MB=50`
- `VIP_LIMIT=0`
- `REFERRAL_URL=https://t.me/CatAcccountGeneratorBot?start=ref_7842341917`
- `DATABASE_PATH=./data/bot.db`
- `ENVIRONMENT=production`
- `WEBHOOK_PATH=/telegram/webhook`
- `WEBHOOK_SECRET` — generated by Render

Render automatically supplies `RENDER_EXTERNAL_URL`; the bot uses it to register the Telegram webhook.

## Local

For local development without a public webhook URL, omit `WEBHOOK_DOMAIN`/`RENDER_EXTERNAL_URL` and the bot falls back to Telegram long polling.

```bash
npm ci
npm start
```

## Security

Never commit `.env` or a Telegram bot token. If a token has been exposed, revoke it with BotFather and create a new one.

The analyzer only classifies status text already present in uploaded TXT files. It does not log into or authenticate against CODM, MLBB, Garena, Moonton, Facebook, Google, or other providers.
